# LIFE 게시판 작업 현황

## 2026-10-28 합의

사용자 요청에 따라 현재 단계는 DB/API 저장을 추가하지 않고 목업 데이터와 sessionStorage를 사용한다.
이는 기존 GitHub 이슈의 영구 저장 조건을 대체하는 이번 로컬 구현의 범위다. GitHub 이슈 본문은 수정하지 않았다.

## 기존 구조 조사

- `App.tsx`: SCHOOL/LIFE 공통 헤더, 모드 선택, 하단 메뉴. 기존 `/life/*`는 준비 중 화면이었다.
- `LifeHomePage.tsx`: 자유·장터·질문 진입 카드가 모두 `/community`로 연결돼 있었다.
- `CommunityPage.tsx`: 안내 화면만 존재하며 게시글 API나 DB 모델은 없었다.
- 기존 홈의 연보라 배경, 흰 카드, LIFE 보라색 강조와 480px 앱 폭을 사용한다.

## 장터 페이지

| 경로 | 기능 |
| --- | --- |
| `/life/market` | 판매/구매 및 판매중/판매완료 필터, 건수, 카드, 글쓰기 진입 |
| `/life/market/new` | 유형·제목·가격·상태·작성 언어·내용·거래 장소 입력 |
| `/life/market/:postId` | 거래 정보·원문·작성 시간·답글 목록 및 작성 |
| `/life/market/:postId/edit` | 내 글 내용과 거래 상태 수정 |

LIFE 홈의 장터 카드와 하단 장터 메뉴가 목록에 연결된다. 기존 공통 헤더와 메뉴 디자인은 유지한다.
개발 모드에서는 기존 홈 미리보기를 장터 하위 경로까지 확장해 체험 사용자로 작성할 수 있다.
프로덕션에서는 기존 로그인 및 프로필 설정 흐름을 거친다.

## 저장과 표시

- 저장 키: `nest:market-demo:v1`. 이 탭의 모든 데모 게시글을 저장한다.
- 작성자 ID는 인증 계정 ID, 개발 미리보기는 `local-preview`다. 계정별로 내 글 수정 여부를 구분한다.
- 게시판 데이터는 같은 탭의 계정 사이에 공유되지만 다른 탭·브라우저·기기와 동기화하지 않는다.
- 최초 저장값이 없으면 한국어 예시 글 2건을 표시한다. 예시 글은 수정할 수 없다.
- 새로고침 후 복원된다. 탭 종료 시 일반적으로 사라지며 브라우저 세션 복원에 따라 남을 수 있다.
- 저장소 실패 시 저장 성공으로 처리하지 않는다. 손상된 데이터는 자동 덮어쓰지 않고 오류를 표시한다.
- 작성자 구분은 데모 UI 동작이며 서버 권한 보장이 아니다.
- 번역 API는 호출하지 않는다. 한국어 예시와 작성 원문·언어를 표시하며 자동 번역 완료로 표현하지 않는다.
- 사진 업로드·채팅·결제·글 삭제는 이번 범위에 포함하지 않는다.

## 질문게시판 — 2026-10-30 구현

| 경로 | 기능 |
| --- | --- |
| `/life/questions` | 학교생활/수업/생활 카테고리, 미해결/해결 필터, 목록 |
| `/life/questions/new` | 제목·내용·카테고리·언어·해결 상태 입력 |
| `/life/questions/:postId` | 질문 상세, 답글 작성, 작성자 해결 상태 변경 |
| `/life/questions/:postId/edit` | 본인 질문 수정 |

질문과 답글은 `nest:questions-demo:v1` 키로 장터와 분리해 저장한다.
질문 작성자만 질문 수정·해결 상태 변경이 가능하며, 답글 수정·삭제는 해당 답글 작성자에게만 허용한다.
개발 미리보기에서는 `local-preview` 사용자를 사용한다. 계정 구분은 기존 로그인 계정 ID를 사용하며 서버 권한 보장은 아니다.
시안과 같은 예시 질문 2건을 한국어 원문으로 제공한다. 실제 자동 번역은 미연동이다.
검증: 질문 추가 테스트 4개 포함 전체 17개, 타입 검사·빌드·lint 통과. 시각/클릭 검증 미실행.

## 검증

- `npm test`: 프로필 8개 + 장터 4개 통과.
- `npm run typecheck`, `npm run lint`, `npm run build` 통과.
- 변경한 프론트 파일의 Prettier 검사 통과.
- 연결 가능한 브라우저가 없어 실제 화면·클릭·모바일 폭의 시각 검증은 미실행.
- 수동 확인: 목록 필터 → 글 등록 → 상세 → 답글 → 수정/판매완료 → 새로고침 → 필터 결과 확인.

## 2026-10-30 답글 수정·삭제

답글 작성자에게만 수정·삭제 버튼을 표시한다. 수정은 인라인 입력 후 저장/취소,
삭제는 확인/취소를 거친다. 변경 함수도 답글 작성자 ID를 검사하며 게시글 작성자는
타인이 쓴 답글을 관리할 수 없다. 저장 실패 시 수정 입력을 유지한다.
개발 미리보기는 모든 비로그인 사용자가 같은 `local-preview` ID를 사용하므로
다른 실제 사용자 구분은 로그인 계정으로 확인해야 한다.

## 질문 해결·삭제 규칙 (2026-10-30)

- 본인의 미해결 질문: 답글 0개면 삭제 가능·해결 불가, 1개 이상이면 삭제 불가·해결 가능. 수정은 가능.
- 해결은 상세 화면에서 선호 언어(ko/en/zh)의 고정 문구와 확인/취소를 거친다. Gemini는 사용하지 않는다.
- 해결된 질문은 수정·삭제·미해결 전환 불가. 답글이 나중에 모두 삭제돼도 잠금은 유지된다.
- 새 질문은 항상 미해결이며 작성·수정 폼에서 상태를 직접 선택할 수 없다. 직접 수정 URL 접근도 차단한다.
- 기존 답글 작성자 권한은 유지한다. 전체 자동 테스트 18개, 빌드·lint 통과. 브라우저 시각 검증은 미실행.

### 해결된 질문의 답글 잠금

해결된 질문에 달린 답글은 작성자도 수정·삭제할 수 없다. 화면의 버튼을 숨기고
`updateQuestionReply`에서도 질문 상태를 검사한다. 미해결 질문의 본인 답글 수정·삭제는 유지한다.
저장 복원 후에도 잠금이 유지되는 자동 테스트를 확인했다.
