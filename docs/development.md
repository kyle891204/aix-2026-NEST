# 개발 원칙과 첫 작업

- 기능별 담당자 1명, 완료 조건, 선행 작업을 이슈에 적는다.
- main은 실행 가능한 상태로 유지한다. 기능 브랜치에서 PR을 만들고 다른 팀원 1명이 검토한다.
- React: 기능 안에 화면·컴포넌트·훅·API를 묶고 공통 HTTP 코드는 `shared/api`를 사용한다.
- Java: 기능별 패키지 안에서 controller → service → repository/외부 연동 책임을 나눈다.
- API·DB 변경은 관련 문서와 예시도 함께 수정한다.
- AI 결과에 날짜·서류·대상을 임의로 추가하지 않는다. 원문과 번역·분석 상태를 분리한다.
- 번역 실패 시 원문과 실패 안내를 제공한다. 중요한 공지를 불확실한 판별로 숨기지 않는다.
- 키·토큰·실제 사용자 공지는 Git과 브라우저 공개 환경변수에 넣지 않는다.
- 고정 UI 번역과 공지/게시글 AI 번역은 별도 방식으로 구현한다.
- DB를 확정하면 JPA·드라이버·마이그레이션을 함께 추가한다. 지금은 DB 없이 기동 가능하도록 했다.
- 일정·타임라인은 후속 범위이며 MVP의 공지·커뮤니티 흐름을 먼저 연결한다.
- AI 도구 사용 기록은 기존 저장소의 `PROMPTS.md` 규칙을 따른다.

## 처음 정할 것

- [ ] 계정 인증 방식과 프로필 필수 항목.
- [ ] DB 종류와 로컬 개발 실행 방식.
- [ ] 공지·게시글 원문과 번역의 데이터 구조.
- [ ] AI 공급자와 비용 상한, 번역 검수자.
- [ ] 실제 한양대 토큰의 과목 공지 조회 검증 담당.
- [ ] 첫 프로필·공지·게시글 API의 요청/응답 계약.
- [ ] 첫 통합 시연 날짜와 배포 환경.

프론트 품질 확인은 타입 검사·Oxlint·Prettier·빌드, 백엔드는 `mvnw verify`를 사용한다. 기능 추가 시 권한·판별·번역 실패처럼 결과에 영향을 주는 경로를 검증한다.
