# 맞춤 공지 대시보드

코드 위치: `frontend/src/features/dashboard/`, 백엔드 `dashboard/`·`matching/`

#6. SCHOOL 홈의 "나에게 해당하는 공지". [전체 공지](notices.md)와 같은 공지·단과대 규칙·분석 결과를 쓴다.

## 홈 화면

- "학교공지 / 과목일정" 두 탭이 있다.
- 대시보드 API는 ‘해당’과 ‘확인 필요’ 공지를 반환한다. 홈의 학교공지 탭에는 ‘해당’ 공지만 표시한다. ‘확인 필요’ 공지는 [전체 공지](notices.md)에서 볼 수 있다.
- 과목일정 탭은 [과목알림](courses.md)의 마감 전 과제를 마감 임박순으로 보여준다(`dashboard/course-schedules.ts`). 과목알림 API를 그대로 쓰므로 LMS 데모가 꺼진 배포에서는 불러오지 못하고, 과목알림에서 데모 암호를 입력하기 전에는 입력 안내를 보여준다.
- 홈에서는 두 탭 모두 최대 3개까지 보여준다(`HOME_LIMIT = 3`). API 기본값 20과 다르다.

## 판별 규칙

`matching/NoticeMatcher`가 판별하며, 공지 목록·상세도 같은 규칙을 쓴다.

아래 순서로 판정한다.

1. 해당 안 됨: 분석이 확실하고 조건 하나라도 명확히 다르다. 다른 조건의 프로필 값이 비어 있어도 이것이 먼저다. 대시보드에서는 뺀다.
2. 확인 필요: 해당 안 됨이 아니면서, 조건에 필요한 프로필 값이 없거나 분석이 확실하지 않거나 아직 분석 전이다.
3. 해당: 분석이 확실하고, 지정된 조건(국적·비자·학위과정·학년)을 모두 만족한다.

- 조건이 비어 있으면 전체 대상이다. 화면에 보여줄 한국어 사유를 항상 1개 이상 붙인다.
- 세부 비자(D-2-1)는 상위 비자(D-2) 공지에 해당한다. 반대는 해당하지 않는다.
- 코드로 읽을 수 없는 프로필 값(자유 텍스트 등)은 값 없음으로 본다. 길이가 길어도 400을 내지 않는다. 석박사통합은 박사과정으로 본다.

## 정한 규칙과 이유

- 팀 결정으로 프로필에 비자를 받지 않는다. 프론트는 `visaType: null`을 보내므로 비자 조건이 있는 공지는 비자 정보가 없어 "확인 필요"가 된다. 다만 분석이 확실하고 국적 등 다른 조건이 명확히 다르면 "해당 안 됨"이다. 버그가 아니다.
- 프로필은 브라우저에만 있어 조회지만 `POST` 본문으로 받고 서버에 저장하지 않는다. 본문이 없거나 맞춤정보 동의를 해제했으면 빈 프로필로 판별한다.
- 해당 공지를 먼저, 각각 마감 임박순으로, 마감 없는 공지는 게시일 최신순으로 둔다. `limit`(기본 20, 1~50)으로 자르기 전에 정렬해 확인 필요 공지가 해당 공지 자리를 차지하지 않게 한다. 마감 지난 공지는 뺀다.
- `collegeId`는 공지를 고를 때만 쓰고 판별에는 쓰지 않는다. 응답의 `missingProfileFields`로 프로필 입력을 안내한다.

API: `POST /api/v1/dashboard?limit=` (로그인 필요). 요청·응답은 [API 계약](../api.md#post-apiv1dashboard)에 있다.
