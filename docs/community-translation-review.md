# 게시글·댓글·답글 자동번역 검수 안내

작업 브랜치: `feat/community-batch-translation`. 커밋·스테이징·푸시는 수행하지 않았다.

## 변경 범위

- 기존 게시판의 데이터 구조, 원문 저장, 작성·수정·삭제, 질문 해결 상태, 필터, 라우트는 유지한다.
- `GeminiClient`에는 묶음 번역 메서드를 추가했다. 기존 단건 번역 메서드·`TranslationService`·`CommunityTranslationController`는 그대로다.
- 새 `BatchTranslationController`와 `BatchTranslationService`가 묶음 경로를 담당한다. 기존 인증·CSRF 인터셉터와 동일 출처 프록시를 사용한다. 새 요청은 현재 세션의 CSRF 토큰을 명시적으로 전달한다.
- `frontend/src/features/translation/`에 화면 항목 수집, 클라이언트 캐시, 공통 훅, 원문 전환·재시도 UI를 추가했다.
- 자유게시판에는 공통 번역 기능을 연결했다. 기존 `title`, `content`, 댓글 `content`는 원문으로 유지한다.
- 팀원 작성 파일인 `MarketPages.tsx`, `QuestionPages.tsx`는 **추가만 수행**했다. 기존 줄을 삭제하거나 교체하지 않았다. 공통 provider·표시 컴포넌트, 답글 작성 언어 선택, 선택한 언어를 새 답글에 반영하는 줄을 추가했다. 기존 CRUD 함수와 스토어는 수정하지 않았다.
- 기존 파일을 일괄 포맷하거나 의존성·환경변수 파일·인증·공지·LMS 코드를 변경하지 않았다.

## 동작

1. 목록에서는 현재 필터에 표시되는 제목·첫 줄 미리보기를 수집한다. 상세에서는 제목·본문·표시 중인 댓글/답글, 장터에 입력된 거래 장소를 수집한다. 작성·수정 화면은 번역하지 않는다.
2. 작성 언어와 선호 언어가 같으면 외부 번역을 요청하지 않는다. 댓글·답글의 작성 언어도 각각 사용한다.
3. 개별 항목의 캐시와 진행 중인 동일 요청을 확인한다.
4. 캐시에 없는 항목만 최대 20개·원문 및 맥락 합계 12,000자씩 묶어서 전송한다. 각 묶음은 Gemini Interactions 요청 한 번으로 처리한다. 토큰 한도와 동일한 기준은 아니며, 사용량을 보면서 조정할 운영값이다.
5. 응답 순서가 아닌 항목 ID로 연결한다. 누락·빈 번역·중복 ID는 해당 항목을 실패 처리한다. 알 수 없는 ID나 해석 불가능한 전체 응답은 묶음을 실패 처리한다. 성공한 결과만 저장한다.
6. 번역 중·실패 시 원문을 계속 표시한다. 화면 상단에서 원문/번역을 전환하며, 전환만으로는 요청하지 않는다. 재시도 시 성공 캐시를 재사용하고 실패 항목만 다시 전송한다.
7. 글 수정·선호 언어 변경 후 이전 응답이 늦게 도착해도 새 화면에 덮어쓰지 않는다. 수정 입력창에는 원문을 넣는다.

목록 미리보기와 상세 본문은 실제 텍스트가 다르면 서로 다른 번역이다. 상세를 열 때 본문 번역을 추가로 요청할 수 있다. 게시판의 기존 표시 개수·페이지 구성을 변경하지는 않았다.

지원 언어는 기존과 같은 한국어·영어·중국어 간체다. 추가 언어 감지 API를 호출하지 않으며, 글쓰기 및 댓글·답글의 작성 언어 선택값을 사용한다.

## DB 없는 캐시

- 새 묶음 경로는 서버 메모리에 성공 항목 최대 200개를 1시간 보관한다. 만료하거나 용량을 넘으면 제거한다. 서버 재시작·재배포 시 초기화되고 서버 인스턴스 간 공유하지 않는다.
- 프론트도 성공 항목 최대 200개를 1시간 메모리에서 재사용한다. 계정별로 구분하며, 번역을 `sessionStorage`나 `localStorage`에 쓰지 않는다. 전체 새로고침 시에는 서버 캐시를 이용할 수 있다.
- 캐시에는 원문·작성 언어·목표 언어·맥락·번역 규칙 버전을 반영한다. 수정된 글에 예전 번역을 사용하지 않는다. 새 글 ID라도 같은 텍스트·조건이면 재사용할 수 있다.
- 기존 단건 API의 캐시는 그대로다. 이번 묶음 캐시와 합치는 리팩터링은 하지 않았다.
- 외부 API를 호출하는 동안 전역 캐시 잠금을 잡지 않으며, 겹치는 동시 요청은 진행 중인 결과를 공유한다.

## 새 API

`POST /api/v1/community/translations/batch`

```json
{
  "targetLanguage": "en",
  "items": [
    {
      "id": "free:post-id:title",
      "text": "같이 공부할 사람 구해요",
      "sourceLanguage": "ko",
      "context": "자유게시판 게시글 제목"
    }
  ]
}
```

- 로그인·CSRF·`Cache-Control: no-store`는 기존 규칙을 따른다.
- 요청은 1~100항목, 항목별 원문 1~3,000자, 맥락 최대 200자, ID 최대 200자이며 ID는 중복될 수 없다. 요청 전체 원문+맥락은 최대 60,000자다. 프론트는 위의 20항목·12,000자 기준으로 먼저 분할한다.
- 항목 결과는 `SUCCEEDED`, `SKIPPED`(같은 언어), `FAILED`로 구분한다. 성공·실패가 혼합된 응답도 HTTP 200이며 항목별 `status`를 확인한다.
- `FAILED`에는 `translatedText: null`, `retryable: true`를 반환한다. 원문을 번역 성공으로 캐시하지 않는다.
- `cached`는 서버 성공 캐시 적중 여부다. 진행 중인 요청을 공유한 경우에는 `false`일 수 있다.

## 직접 검수할 순서

기존 프론트·백엔드 실행 방법과 `GEMINI_API_KEY`, 모델 설정을 그대로 사용한다. 실제 번역은 로그인 세션이 필요하다. 프론트 개발 미리보기만 열고 백엔드 인증이 없는 경우 원문·실패·재시도가 표시될 수 있다.

1. 선호 언어를 한국어로 설정한 뒤 자유게시판을 연다. 영어·중국어 예시 제목과 미리보기가 번역되고 한국어 글은 원문 그대로인지 확인한다.
2. `원문 보기`를 눌러 원래 제목·본문을 확인하고 다시 `번역 보기`로 전환한다. 개발자 도구에서 이 전환으로 번역 요청이 늘지 않는지 확인한다.
3. 상세에서 작성 언어를 English로 선택해 영어 댓글을 등록한다. 새 댓글만 번역되는지 확인한다.
4. 번역된 내 댓글의 `수정`을 누른다. 번역문이 아닌 원문이 입력창에 표시되는지 확인한다. 원문을 수정해 저장하고 새 번역을 확인한다.
5. 장터·질문에서도 다른 언어의 답글을 등록해 동일한 흐름을 확인한다. 기존 거래 상태·질문 해결·작성자 권한이 유지되는지 확인한다.
6. 같은 글을 다시 방문한다. 프론트 메모리 또는 서버 캐시에서 재사용되는지 확인한다. 서버 `cached`는 성공 캐시가 실제 적중한 경우만 true다.
7. 선호 언어를 변경하고 이전 언어의 번역이 새 화면에 남지 않는지 확인한다.
8. 테스트 환경에서 API 오류를 발생시키거나 모의 공급자 응답을 사용한다. 원문이 읽히고 `실패한 번역 재시도`가 표시되는지 확인한다. 정상 응답 복구 뒤 실패 항목만 다시 요청되는지 확인한다.

## 검증 기록 · 2026-11-07

- 기존 기능을 포함한 프론트 테스트 75개, 타입 검사, lint, 프로덕션 빌드가 모두 통과했다. 번역 테스트는 요청 횟수, 캐시·만료·수정·계정 구분, 동시 요청, 분할, ID 검증, 일부 실패 후 재시도, 프록시·CSRF 전달을 검증한다.
- 기존 백엔드와 새 캐시·배치·동시 요청·인증·CSRF·입력 검증을 포함한 테스트 131개가 모두 통과했다. Gemini 클라이언트의 HTTP 직렬화·완료 상태·응답 파싱은 로컬 공급자 테스트로 별도 검증했다.
- 실제 Gemini에 가상 한국어 게시글과 중국어 답글 2개를 **한 요청**으로 보내 두 ID의 영어 번역이 반환되는 것을 확인했다. 날짜·시간이 포함된 가상 게시글은 `See you at the library tomorrow at 3 PM.`으로 반환됐다. 실제 이용자 글·LMS 자료를 검증에 사용하지 않았다.
- 일반 Chrome에서 자유게시판 번역/원문 전환, 영어 댓글 자동번역, 댓글 수정창의 원문, 장터·질문의 영어 답글 자동번역을 확인했다. 화면 검증은 외부 호출을 추가 소모하지 않는 임시 모의 Gemini 공급자를 사용했다. 임시 공급자와 가상 프로필은 제품 코드·설정에 포함하지 않았다.
- 앱 내장 브라우저에서는 이 로컬 검증 환경의 세션이 유지되지 않아 CSRF 실패가 발생했으며, 일반 Chrome에서 정상 세션과 번역 표시를 확인했다.

기계번역의 모든 문장에 대한 정확성은 보장하지 않는다. 원문 전환은 항상 제공하며, 실제 운영 모델의 사용량·지연·번역 품질은 팀 검수에서 추가 확인한다.
