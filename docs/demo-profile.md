# 계정별 프로필 데모 — Context + sessionStorage

Google 인증과 서버 세션은 기존 백엔드를 사용한다. 프로필은 서버나 DB로 전송하지 않고
브라우저의 현재 탭에 저장한다. 이는 회원 DB와 서버 동의 이력을 구현한 것이 아니며,
저장된 체크값을 제품 API의 인증·권한 판단에 사용하지 않는다.

## 실행과 사용자 흐름

기존 `docs/authentication.md`에 따라 Google 클라이언트 ID를 설정하고 백엔드와 프론트를 실행한다.
계정별 저장을 시험하려면 실제 로그인이 필요하다. 개발 모드의 기존 비로그인 홈 미리보기에는
개인 프로필이 표시되지 않는다.

1. `/login`에서 Google 로그인한다.
2. 이 계정의 저장값이 없으면 `/signup/consent`에서 A01 동의 → A02 입력으로 이동한다.
3. A02의 다음 버튼을 누르면 프로필을 저장하고 학교 홈으로 바로 이동한다.
   다른 화면에서 로그인·수정을 시작한 경우에는 원래 요청한 앱 화면으로 돌아간다.
4. 학교 홈의 내 정보를 펼치면 닉네임·학교·단과대학·학과·과정·학년·국적·언어를 확인할 수 있다.
5. 개인정보 수정 → 프로필·동의 수정에서 값을 변경하고 다시 저장할 수 있다.
6. 로그아웃하면 화면과 입력 중인 값은 비워지지만 계정별 저장값은 삭제하지 않는다.
7. 같은 탭에서 같은 계정으로 로그인하면 저장값을 복원한다. 다른 계정은 별도로 설정한다.

맞춤정보 동의를 해제한 뒤 저장하면 선택 개인정보를 비운다. 비자·학번은 가입 입력이나
프로필 저장 항목에 포함하지 않는다. 선택 항목을 비워도 가입 흐름을 진행할 수 있다.
공지 카드는 검토용 예시이며, 저장한 프로필로 실제 해당 여부를 판별한 결과가 아니다.

## 저장 범위

- 키: `nest:demo-profile:v1:<인증된 계정 ID>` (ID는 URL 인코딩).
- 값: 스키마 버전, 계정 ID, 데모용 동의 선택, 지원되는 프로필 필드만 저장한다.
- Google 토큰·비밀번호·세션 쿠키는 저장하지 않는다. 계정 ID는 기존 인증 응답의 `user.id`다.
- A01/A02의 작성 중인 값은 메모리에만 있으며, A02에서 다음을 눌러야 저장된다.
- 새로고침과 같은 탭의 재로그인에서는 복원된다. 다른 기기·브라우저·원본(URL 호스트/포트)과 공유하지 않는다.
- 탭을 닫으면 일반적으로 삭제된다. 브라우저의 세션 복원 기능이나 탭 복제는 저장값을 복원·복사할 수 있다.
- JSON 손상·버전 불일치·계정 불일치·유효하지 않은 학과 조합은 미설정으로 처리한다.
- 브라우저 저장소 접근이나 쓰기가 실패하면 완료로 표시하지 않고 재시도 안내를 제공한다.

## 구조

- `frontend/src/features/profile/demo-profile.ts`: 타입, 입력 검증, 필드 초기화, 계정별 저장·복원.
- `DemoProfileProvider.tsx`: 계정별 Context. 계정 ID가 바뀌면 하위 화면까지 새로 만들어 이전 계정의 값이 남지 않는다.
- `demo-profile-context.ts`: 공통 조회·저장 인터페이스.
- `profile-display.ts`: 학교 홈과 내 계정 화면에서 사용하는 표시값.
- `frontend/src/features/auth/SignupPage.tsx`: 로그인 확인, A01/A02, 저장 성공·실패 처리.

저장 전용 API, DB 의존성, 백엔드의 가입 완료 권한은 이번 변경에서 추가하지 않는다.
향후 DB를 도입할 때 계정별 저장·조회 함수를 서버 API로 대체하고, 서버의 가입·동의·소유권 검사를 구현한다.

## 검증

프론트 디렉터리에서 `npm test`, `npm run build`, `npm run lint`를 실행한다.
Node 24의 내장 테스트 실행기로 별도 테스트 패키지 없이 저장소 검증을 실행한다.

가상 계정의 별도 로컬 인증 응답으로 A 저장 → 새로고침 → 로그아웃 → B 신규 설정 →
B 로그아웃 → A 재로그인 → A 프로필 복원을 브라우저에서 확인했다.
테스트용 인증 서버는 저장소 코드와 배포 산출물에 포함하지 않는다.
실제 Google 팝업과 배포 원본의 로그인·쿠키 전달은 배포 후 추가 확인한다.

검토용 원본에 있던 `src/app/home.css`, `src/features/life/life.css`의
기존 포맷 문제는 별도 정리가 필요하다.
